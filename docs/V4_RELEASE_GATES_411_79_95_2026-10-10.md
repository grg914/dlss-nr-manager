## #411 — twelve approved model assets, immutable future release

The five published v3.2.0 NCNN `.param` assets were CRLF-converted and are incompatible with the application's hard-pinned LF byte sizes/Git blobs. Correcting the release workflow (#413) prevents recurrence; it does not fix existing v3.2.0 downloads.

`tools/verify-realesrgan-model-candidate.ps1` is now wired **after** the existing raw Git blob copy gate and **before** checksum generation/publication in `.github/workflows/release.yml`. It reads the exact twelve `RequiredModels` records from `AiUpscaleService.cs` and fails closed on count, duplicate/unknown file, URL/name inconsistency, missing file, size, unfiltered Git blob SHA-1 and computed SHA-256. It creates `realesrgan-model-manifest.json` containing the exact source commit and 12 independently hashable receipts. The release workflow includes that file in `SHA256SUMS.txt` and the immutable release upload set.

Operator-only candidate check, against **the exact staged release-assets directory from a source-identical checkout with Git LFS materialized**:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-realesrgan-model-candidate.ps1 -AssetDirectory .\release-assets -SourceFile .\Services\AiUpscaleService.cs -ManifestPath .\release-assets\realesrgan-model-manifest.json
```

Passing this check proves only the local staging receipt, not that GitHub has published identical bytes. **Do not create/modify an existing tag or release.** Before a new authorized V4 release, capture the exact intended tag/commit, compare GitHub release asset IDs, content lengths and GitHub SHA-256 digests against every local receipt, then actually download the assets and verify hashes. The application currently uses mutable `/releases/latest/download` URLs; plan immutable release-tag or asset-ID pinning for the finalized V4 package after the release identity is approved. Never repin to the known-bad CRLF artifacts. On actual Windows RTX, test fresh install, repair, interruption, offline cache and hash rejection. #411 stays open until those proofs exist.

## #79 — selected path: licensed official Microsoft REDIST, fail closed

**Primary choice:** preserve the current Microsoft-signed, unmodified x64 `VC/Redist/MSVC` provenance gate and only enable `DLSSNR_OPENMP_REDIST_APPROVED` following documented approval by the actual redistributor. - https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files

**Fallback:** prepare an experimental `-DisableOpenMp` Real-ESRGAN build on an isolated Windows developer machine. Run both direct and packaged PE audits:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\build-realesrgan.ps1 -BuildPath .\build-realesrgan-no-openmp -Clean -DisableOpenMp
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\audit-realesrgan-openmp.ps1 -ExecutablePath .\build-realesrgan-no-openmp\realesrgan-ncnn-vulkan.exe
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\audit-realesrgan-package-openmp.ps1 -PackageDirectory <EXACT_STAGED_PACKAGE_DIRECTORY> -ReportPath (Join-Path $env:TEMP 'realesrgan-pe-imports.json')
```

The new package audit inspects direct PE imports of **every shipped EXE and DLL** and rejects named OpenMP DLL dependencies. It does not prove the absence of delay-loaded/dynamically loaded OpenMP, transitive imports from system DLLs, or equivalence in GPU performance. No OpenMP-free candidate is approved until x2/x4 photo/anime images, VRAM, RAM, throughput, output quality and long-run stability are recorded on actual RTX hardware. Keep #79 open and Real-ESRGAN binary publishing disabled until the chosen path is fully evidenced.
