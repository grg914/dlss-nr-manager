17. DÉCISIONS TECHNIQUES

Décision :
Séparer circuit production et circuit refresh.
Raison :
Rendre Build/Release normaux indépendants de la disponibilité des upstreams.
Alternative :
Télécharger les dernières dépendances pendant chaque build/release.
Solution retenue :
Sources vendored + locks immuables + runtime-seed-v1.
Conséquence :
Plus de contrôle et reproductibilité ; refresh circuit plus complexe.

Décision :
NuGet offline manager-owned.
Raison :
Éviter NuGet.org pendant Build/Release production.
Alternative :
dotnet restore public.
Solution retenue :
nuget-offline.zip + NuGet.Config avec sources vidées.
Conséquence :
Seed volumineux mais production déterministe.

Décision :
Java 25 manager-owned pour Minecraft.
Raison :
Éviter WinGet / installation globale.
Alternative :
installer Temurin via WinGet.
Solution retenue :
temurin-25-jre-win-x64.zip validé SHA-256 et java -version.
Conséquence :
Runtime privé à l'application.

Décision :
Composants NVIDIA restreints en notify-only/local-only lorsque nécessaire.
Raison :
Contraintes de licence et nécessité de SDK local.
Alternative :
publier le SDK brut.
Solution retenue :
ne pas redistribuer les matériaux restreints.
Conséquence :
Certaines promotions nécessitent une validation/build local autorisé.

Décision :
Dynamic FPS sélectionné par release compatible Minecraft 26.2.
Raison :
La dernière release globale cible 26.3.
Alternative :
suivre latest sans filtre.
Solution retenue :
latest-compatible-release + filtre asset Fabric 26.2.
Conséquence :
Le projet reste sur 3.11.9 pour Minecraft 26.2 tant qu'aucune release 26.2 plus récente n'existe.
