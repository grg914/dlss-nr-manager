En général, dans un projet GitHub avec plusieurs branches :

main (ou master) → contient la version stable du projet.
develop → peut contenir la version en cours de développement.
feature/... → une branche par fonctionnalité ou tâche.
bugfix/... → une branche pour corriger un bug.
Quand une fonctionnalité est terminée, on fait généralement :

feature/ma-fonctionnalite
          ↓
       develop
          ↓
         main
Donc oui, les branches de travail sont généralement fusionnées à un moment donné, mais on ne fusionne pas toutes les branches directement dans main à la fin.

Exemple
Vous avez :

main
 └── develop
      ├── feature/login
      ├── feature/paiement
      └── feature/profil
Une fois feature/login terminée :

feature/login → develop
Puis feature/login peut être supprimée, puisqu'elle n'est plus nécessaire.

Ensuite, quand develop est suffisamment stable :

develop → main
Les trois fonctionnalités se retrouvent alors dans main.

À retenir : une branche feature est généralement temporaire. Elle sert à travailler séparément, puis elle est fusionnée dans la branche de développement/principale et peut être supprimée.
