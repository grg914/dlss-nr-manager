# Support

## Bugs

Use a GitHub issue for reproducible application bugs.

Include, when relevant:

- DLSS NR Manager version or commit;
- Windows version;
- GPU model and driver;
- affected feature;
- exact error text;
- reproduction steps;
- whether the affected component came from the manager-owned Downloads/runtime channel.

Review logs for sensitive information before attaching them.

## Security

Do not publish exploit details, secrets, credentials, private SDK files, or sensitive payloads in a normal issue.

Follow [SECURITY.md](SECURITY.md) and use GitHub's private vulnerability reporting flow for security vulnerabilities.

## Licensing and redistribution

For redistribution/source questions, use:

- [Third-party notices](docs/THIRD_PARTY_NOTICES.md)
- [Source availability](SOURCE_AVAILABILITY.md)
- [Release artifact policy](docs/RELEASE_ARTIFACT_POLICY.md)
- the exact upstream license for the affected component

A public download URL alone is not proof that redistribution is permitted.

## Runtime/download issues

For install or download problems, include:

- component/model id;
- package/release tag;
- expected total size when shown;
- failed asset/chunk name;
- SHA/integrity error text;
- whether retry/remove/redownload was attempted.

Do not attach restricted model weights or license-restricted SDK binaries to public issues.
